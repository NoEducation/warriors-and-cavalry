# Economy Stage — Game Time, Resources, Stockpile, Production Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Game time passes in fixed ticks and shows in the HUD; the player has wood, stone and food; buildings cost resources, storage buildings hold them and production buildings add to them over time.

**Architecture:** `src/sim/` gains a tick (`World.tick()`), an `Economy` (amounts and capacities) and `Production` (per-building cycles); all of it stays deterministic and changes only through `World.apply` and `World.tick`. `src/game/` gains a `SimulationRunner` that turns frame time into ticks. `src/ui/` gains a resource bar, a clock and costs on the build bar. `src/render/` gains four building shapes, stockpile stacks and growing crops, which read the world each frame.

**Tech Stack:** Node 26, TypeScript 7 (strict), Vite 8, Three.js 0.187, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-11-12-economy-design.md` — read it before starting any task.

## Global Constraints

- Project root: `D:\Projekty\warriors-and-cavalry`. Work on branch `economy`. Never push; never touch `main`.
- `AGENTS.md` is binding: layers, simulation purity, one class per file, explicit modifiers and return types, doc comments on public methods, named interfaces for data, no `enum`, files under about 150 lines, no new dependencies, no asset files.
- Authorship: commits carry no `Co-Authored-By` trailer and no AI or tool attribution of any kind.
- All simulation time is whole ticks. Nothing in `src/sim` reads a clock. Every per-tick loop over objects runs in ascending id order.
- The world changes only through `World.apply(command)` and `World.tick()`; render, UI and game code only read it.
- Numbers from the spec are data, not code: costs, footprints, storage and production values live in the `OBJECT_KINDS` table; start amounts and base capacity in `ECONOMY_CONFIG`; tick rates in `gameTime.ts`.
- Small commits with descriptive messages; `npm test` and `npm run build` pass on the last commit of every task.

## Review Focus

1. **Tab left in the background, then reopened** — at most 10 ticks run in the next frame and the backlog is dropped; no burst of thousands of ticks. (Task 1 test.)
2. **Demolishing a Stockpile that holds more than the remaining capacity** — amounts are clamped to the new capacity, never negative or NaN, and the refund cannot push an amount over capacity. (Task 2 test.)
3. **Paying with exactly what you have** — a cost equal to the amount is accepted and leaves 0; one unit short is rejected and changes nothing. (Task 2 test.)
4. **Production into nearly full storage** — a yield that only partly fits stores what fits and the cycle restarts; at capacity the cycle does not advance, and resumes after spending. (Task 3 tests.)
5. **Space or +/- while a button has focus, or held down** — toggles once per press, does not click the focused button, does not scroll the page. (Task 1 test and browser check.)

### Task 3: Production

**Files:**
- Create: `src/sim/Production.ts`
- Modify: `src/sim/World.ts`, `src/sim/worldChecksum.ts`
- Test: `tests/Production.test.ts`, `tests/worldChecksum.test.ts`

**Interfaces:**
- Consumes: `OBJECT_KINDS[kind].production`, `Economy.add`, `World.objects()`.
- Produces:
  - `type ProductionStatus = 'working' | 'noTrees' | 'storageFull'`; `interface ProductionState { readonly status: ProductionStatus; readonly progress: number; readonly cycleTicks: number }`.
  - `World.productionState(objectId: number): ProductionState | null` — `null` for objects that do not produce.
  - `World.tick()` now also advances production. For each producing building in ascending id order: if it needs trees and none stands within `treeRadius` tiles of its footprint (Chebyshev distance from the footprint rectangle) → `noTrees`, no progress; else if its resource is at capacity → `storageFull`, no progress; else progress + 1, and on reaching `cycleTicks` add the yield (storing what fits) and reset progress to 0.
  - `class Production` owns the per-building progress and the tree check; `World` creates it, tells it when buildings are added or removed, and calls it from `tick()`. The tree check must not rescan the map every tick: cache the result per building and recompute only when a tree is removed.
  - `worldChecksum` also covers each producing building's progress, in id order.

- [ ] **Step 1: Write failing tests** on small hand-built worlds (flat grass; trees via `spawn`; resources adjusted by placing/demolishing as needed):
  - Woodcutter's hut with a tree 3 tiles away: after 99 ticks wood is unchanged and `progress` is 99; after the 100th tick wood is +2 and `progress` is 0; status `working`.
  - Woodcutter's hut with the nearest tree 8 tiles from the footprint works; at 9 tiles its status is `noTrees` and wood never changes over 500 ticks.
  - Quarry (placed next to rock): +2 stone after exactly 150 ticks. Wheat farm: +3 food after exactly 200 ticks.
  - Storage full: with wood at capacity the hut's status is `storageFull` and progress stays where it was; after wood is spent (place a building) it resumes from that progress.
  - Partial fit: with wood at capacity − 1 when a cycle completes, wood ends at capacity and progress resets to 0.
  - Two huts placed on different ticks complete on their own schedules (offset preserved).
  - Demolishing a producer removes its state (`productionState` is `null`) and it no longer adds resources.
  - `productionState` is `null` for a Hovel and a Tree.
  - Determinism: two worlds from the same seed given the same commands on the same ticks have equal `worldChecksum` after 1000 ticks; changing one command's tick changes it.
  - Speed: 2400 ticks on a 512 × 512 generated world with 20 producing buildings take under 200 ms (generous limit; report the measured time).
