# Peasants Stage — Peasants, Pathfinding, Supply Chain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Peasants arrive at the Keep, walk the map along found paths, staff production buildings and carry each batch to the nearest storage place, where it is added to the totals.

**Architecture:** All rules live in `src/sim`: a `PathFinder` (multi-goal A* on the tile grid), a `Population` that owns peasants (arrivals, leaving, jobs, walking, carrying), and `Production` changed to hand finished batches to workers instead of adding them to the economy. `World.tick()` runs population before production. `src/render` gets a `PeasantLayer` drawn with instancing and interpolated by the tick fraction; `src/ui` shows the population.

**Tech Stack:** Node 26, TypeScript 7 (strict), Vite 8, Three.js 0.187, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-11-25-peasants-design.md` — read it before starting any task.

## Review Focus

1. **A building placed on the tile a peasant is standing on** — the peasant still finds a way off it (start tile exempt) and carries on; nothing throws. (Task 1 test, Task 3 test.)
2. **Demolishing the Keep while peasants exist** — housing drops to the Hovels' total, extra peasants leave idle-first, nobody new arrives, the rest keep working. (Task 2 test.)
3. **A workplace or target storage demolished while a worker walks to it** — the worker becomes idle (workplace) or re-targets (storage) on the next tick; no peasant points at a missing building. (Task 3 tests.)
4. **No path at all** (building on an island, or walled in by other buildings) — the search stops at the limit within the time budget, the worker gives up the job and the building is skipped for 200 ticks; no tick takes a full-map search per peasant. (Task 1 and Task 3 tests.)
5. **"New map" with walking, carrying peasants** — all peasant meshes are freed, the new world starts with none, and `renderer.info.memory.geometries` does not grow. (Task 4 test and browser check.)

### Task 1: Path-finder

**Files:**
- Create: `src/sim/PathFinder.ts`, `src/sim/MinHeap.ts`, `src/sim/pathConfig.ts`
- Modify: `src/sim/World.ts` (walkability and access tiles only)
- Test: `tests/PathFinder.test.ts`, `tests/MinHeap.test.ts`, `tests/World.test.ts`

**Interfaces:**
- Produces:
  - `PATH_CONFIG = Object.freeze({ maxExpanded: 65536, straightCost: 10, diagonalCost: 14 })`.
  - `type IsWalkable = (tx: number, ty: number) => boolean`.
  - `class MinHeap` — binary heap of node indices ordered by a numeric key, ties by smaller node index: `push(node: number, key: number): void`, `pop(): number` (−1 when empty), `get size(): number`, `clear(): void`.
  - `class PathFinder`:
    - `constructor(width: number, height: number)` — allocates its search arrays once (typed arrays sized `width × height` plus a search-generation stamp so a new search needs no clearing).
    - `find(start: TileCoord, goals: readonly TileCoord[], isWalkable: IsWalkable): TileCoord[] | null` — A*, 8 directions, step costs from `PATH_CONFIG`, no corner cutting (a diagonal needs both side tiles walkable), heuristic = smallest octile distance to any goal, ties in the open set broken by the smaller `ty * width + tx`. The start tile need not be walkable. Returns the tiles to walk in order, excluding the start and ending on the goal reached first; `[]` when the start is a goal; `null` when no goal is reachable, `goals` is empty, or more than `PATH_CONFIG.maxExpanded` tiles were expanded.
    - `get lastExpanded(): number` — tiles expanded by the last `find` (for tests and reports).
  - `World.isWalkable(tx: number, ty: number): boolean` — in bounds, not `Water`, and no object or a Tree on the tile.
  - `World.accessTiles(objectId: number): TileCoord[]` — the walkable tiles of `Footprint.edgeNeighbours()` for that object, in that (row-major) order; `[]` for an unknown id.

### Task 2: Population — peasants, housing, arrivals, leaving, walking

**Files:**
- Create: `src/sim/Peasant.ts`, `src/sim/Population.ts`, `src/sim/populationConfig.ts`
- Modify: `src/sim/ObjectKind.ts`, `src/sim/World.ts`, `src/sim/worldChecksum.ts`
- Test: `tests/Population.test.ts`, `tests/worldChecksum.test.ts`

**Interfaces:**
- Consumes: `PathFinder`, `World.isWalkable`, `World.accessTiles`, `Economy`.
- Produces:
  - `ObjectKindInfo.housing: number` — Keep 4, Hovel 4, every other kind 0.
  - `POPULATION_CONFIG = Object.freeze({ arrivalTicks: 50, arrivalFoodCost: 5, retryTicks: 50, unreachableSkipTicks: 200, straightStepTicks: 4, diagonalStepTicks: 6 })`.
  - `type PeasantState = 'idle' | 'toWork' | 'working' | 'toStore' | 'toWorkBack'`.
  - `interface Load { readonly resource: ResourceKind; readonly amount: number }`.
  - `interface PeasantView { readonly id: number; readonly state: PeasantState; readonly tx: number; readonly ty: number; readonly nextTx: number; readonly nextTy: number; readonly stepProgress: number; readonly stepTicks: number; readonly load: Load | null; readonly workplaceId: number | null }` — when not moving, `next = (tx, ty)` and `stepTicks = 0`.
  - `class Population` (owned by `World`, not exported through it):
    - `constructor(world: PopulationHost, economy: Economy)` with `interface PopulationHost { readonly map: GameMap; isWalkable: IsWalkable; accessTiles(objectId: number): TileCoord[]; objectById(id: number): MapObject | undefined; objects(): Iterable<MapObject> }` (add `World.objectById` if missing).
    - `buildingAdded(object: MapObject): void`, `buildingRemoved(object: MapObject): void` — housing bookkeeping (and, from Task 3, jobs).
    - `tick(): void` — this task: arrival/leaving, then each peasant advances its walk (ascending id).
    - `peasants(): Iterable<PeasantView>`, `get count(): number`, `get housing(): number`, `get idleCount(): number`, `get arrivalTimer(): number`.
    - For this task a walk can be started by an internal method `walkTo(peasant, goals: readonly TileCoord[])`; idle peasants stand still. Task 3 drives walks from jobs.
  - `World`: `peasants(): Iterable<PeasantView>`, `get population(): PopulationSummary` with `interface PopulationSummary { readonly count: number; readonly housing: number; readonly idle: number }`; `tick()` runs population before production; `add`/`demolish` notify the population after production and before listeners.
  - Arrival rules (from the spec): the Keep with the lowest id is the arrival point; while `count < housing` and food ≥ `arrivalFoodCost`, `arrivalTimer` counts up; at `arrivalTicks` it spends the food, adds a peasant on the Keep's first access tile in the order bottom edge (`ty = keep.ty + height`) left→right, right edge top→bottom, top edge left→right, left edge top→bottom, and resets the timer to 0. If either condition fails, or the Keep has no access tile, the timer resets to 0.
  - Leaving: whenever `count > housing`, remove peasants until it fits: idle ones first by highest id, then the rest by highest id. A removed peasant's load is lost.
  - Walking: a step to a straight neighbour takes `straightStepTicks`, a diagonal one `diagonalStepTicks`. Before starting a step, if the next tile is no longer walkable, search again from the current tile toward the same goals (Task 3 adds goal recomputation).
  - `worldChecksum` also covers the arrival timer and, per peasant in id order: id, state index, tx, ty, nextTx, nextTy, stepProgress, load resource (−1 when none) and amount, workplace id (0 when none).

### Task 3: Jobs and the supply chain

**Files:**
- Modify: `src/sim/Population.ts` (or split out `src/sim/Jobs.ts` / `src/sim/WorkerTrips.ts` if it nears 150 lines), `src/sim/Production.ts`, `src/sim/World.ts`, `src/sim/worldChecksum.ts`
- Test: `tests/Supply.test.ts`, `tests/Production.test.ts`, `tests/Population.test.ts`

**Interfaces:**
- Consumes: Task 1 and Task 2 interfaces.
- Produces:
  - `Production.tick(workerPresent: (buildingId: number) => boolean): ProductionOutput[]` with `interface ProductionOutput { readonly buildingId: number; readonly resource: ResourceKind; readonly amount: number }` — a producer advances only when `workerPresent(id)` and its own conditions hold (trees, capacity); a finished cycle is returned, not added to the economy.
  - `ProductionStatus` becomes `'working' | 'noTrees' | 'storageFull' | 'noWorker' | 'workerOnTheWay' | 'workerDelivering' | 'workerCannotReach'`. `World.productionState(id)` reports, in this priority: `noWorker` (no worker and not skipped), `workerCannotReach` (building skipped after a failed search), `workerOnTheWay` (state `toWork`), `workerDelivering` (state `toStore` or `toWorkBack`), otherwise Production's own `working` / `noTrees` / `storageFull`.
  - `Population.collect(outputs: readonly ProductionOutput[]): void` — gives each batch to its building's worker as a load and starts `toStore`.
  - Storage places: for wood and stone, Stockpiles and Keeps; for food, Granaries and Keeps. `toStore` searches once with the access tiles of every storage place for that resource as goals. On arrival the load goes into the economy through `Economy.add` (excess lost), then the worker searches back to its workplace (`toWorkBack`); on arrival there it is `working` again.
  - Jobs: each tick, after arrivals/leaving and before walking, each idle peasant (ascending id) takes the vacant producer with the lowest id that is not skipped, and starts `toWork`. If the search fails, the peasant gives the job up (idle) and the building is skipped for `unreachableSkipTicks`.
  - No storage place reachable or existing while carrying: the worker waits where it is and tries again every `retryTicks`.
  - A trip remembers its goal building id. The peasant searches again (recomputing the goal tiles from `accessTiles`, and the storage target when delivering) when its next tile is unwalkable, and when its path is used up but it is not on an access tile of the goal building.
  - Demolished workplace: its worker becomes idle where it stands and its load is lost. Demolished target storage: the carrier re-targets on its next tick.
  - `worldChecksum` also covers each skipped building's remaining skip ticks (in building id order).

- [ ] **Step 1: Write failing tests** on small hand-built flat-grass worlds with trees spawned near the hut:

  - demolishing the target Stockpile mid-trip: the worker re-targets to the Keep and delivers there.
  - demolishing the workplace while `working`: the worker is idle, load `null`, and another vacant job is taken on the next tick if one exists.
  - unreachable: a hut on a tile area fully ringed by water from the Keep → the worker gives the job up, status `workerCannotReach` for 200 ticks, then the job is offered again.
  - two huts, one peasant: the lower-id hut gets the worker.

  - determinism: two worlds from the same seed (512 × 512) with the same commands on the same ticks (a Keep, two Hovels, a hut, a quarry, a farm, a Stockpile, a Granary) have equal checksums after 3000 ticks.
  - speed: that 3000-tick run with 40 peasants (Keep plus 9 Hovels, food raised through the injected `Economy`) completes in under 500 ms (generous; report the time).

### Task 4: Drawing peasants and showing the population

**Files:**
- Create: `src/render/PeasantLayer.ts`, `src/render/PeasantGeometryFactory.ts`
- Modify: `src/render/WorldLayer.ts`, `src/render/WorldView.ts`, the four existing layers (signature only), `src/game/SimulationRunner.ts`, `src/game/Game.ts`, `src/game/StatusDisplay.ts`, `src/game/TileHover.ts`, `src/ui/ResourceBar.ts`
- Test: `tests/PeasantLayer.test.ts`, `tests/SimulationRunner.test.ts`, `tests/peasantText.test.ts` (or wherever the text helper lands)

**Interfaces:**
- Consumes: `World.peasants()`, `World.population`, the new production statuses.
- Produces:
  - `SimulationRunner.tickFraction: number` — the not-yet-run fraction of a tick, in `[0, 1)`; 0 while paused.
  - `WorldLayer.update(tickFraction: number): void` and `WorldView.update(tickFraction: number): void` (existing layers ignore the argument).
  - `class PeasantLayer implements WorldLayer` — `constructor(world: World)`; one `InstancedMesh` for bodies and one for carried bundles, created once with room for `PEASANT_CAPACITY = 256` instances (grow by doubling if exceeded, disposing the old one); each frame sets `count` and matrices from `world.peasants()`. Position: tile centre of `(tx, ty)` moved toward `(nextTx, nextTy)` by `(stepProgress + tickFraction) / stepTicks` (clamped to 1; no movement when `stepTicks` is 0), height from the two tiles' `map.tileHeight` by the same fraction, facing the direction of travel. Bundle colour per resource through `setColorAt` (wood `0x6b4a2b`, stone `0x9a9a94`, food `0xd9b93a`); peasants without a load have no bundle instance. `dispose()` frees both meshes, geometries and materials.
  - `PeasantGeometryFactory.create(): THREE.BufferGeometry` — a merged low-poly figure (legs/body/head, vertex colours, under 60 triangles, about 0.8 world units tall) and `createBundle(): THREE.BufferGeometry` (a small box sized for the back).
  - `ResourceBar.update(economy: EconomyView, population: PopulationSummary): void` — appends ` · Peasants 3/8`, plus ` (2 idle)` when any are idle; DOM written only on change.
  - Hover text for the new statuses: `no worker`, `worker on the way`, `worker delivering`, `worker cannot reach`.
  - `Game` passes `runner.tickFraction` to `WorldView.update`; `WorldView.showWorld` adds the `PeasantLayer`. `Game.ts` stays at or under 150 lines.
