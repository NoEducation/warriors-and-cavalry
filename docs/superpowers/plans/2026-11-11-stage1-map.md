# Stage 1 — Generated 3D Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser page showing a seeded, procedurally generated, pixelated 3D terrain map with an RTS camera (pan, zoom, rotate) and a highlight on the hovered tile.

**Architecture:** Two layers with a one-way dependency. `src/sim/` is plain deterministic TypeScript (PRNG, noise, map data, map generation) with no three.js or browser APIs, so it can later run on a server. `src/render/` uses three.js to draw the sim state and handle input; it never mutates sim state. `src/main.ts` wires them together.

**Tech Stack:** Node 26.13.1, TypeScript 7, Vite 8, Three.js 0.187, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-11-11-stage1-map-design.md` — read it before starting any task.

### Task 2: Seeded PRNG and noise

**Files:**
- Create: `src/sim/rng.ts`, `src/sim/noise.ts`
- Test: `tests/rng.test.ts`, `tests/noise.test.ts`
- Delete: `tests/smoke.test.ts`

**Interfaces:**
- Produces:
  - `mulberry32(seed: number): () => number` — each call returns a float in `[0, 1)`.
  - `hash2(seed: number, x: number, y: number): number` — integer `x`, `y`; returns a float in `[0, 1)`; pure function of its inputs.
  - `valueNoise2(seed: number, x: number, y: number): number` — float `x`, `y`; returns `[0, 1)`; continuous.
  - `fbm2(seed: number, x: number, y: number, octaves: number): number` — returns `[0, 1)`.

- [ ] **Step 1: Write failing tests.**
  - `mulberry32`: two generators with seed `42` give the same first 100 values; seeds `1` and `2` give different first values; 10 000 values are all `>= 0` and `< 1`; their mean is between `0.45` and `0.55`.
  - `hash2`: `hash2(7, 3, 5) === hash2(7, 3, 5)`; differs from `hash2(7, 5, 3)` and from `hash2(8, 3, 5)`; negative coordinates `hash2(7, -3, -5)` return a value in `[0, 1)`.
  - `valueNoise2`: at integer coordinates equals `hash2(seed, x, y)`; all values over a 50×50 grid sampled at step `0.37` are in `[0, 1)`; `|valueNoise2(s, x, y) - valueNoise2(s, x + 0.001, y)| < 0.01` for 100 sample points.
  - `fbm2`: repeatable; in `[0, 1)` over the same grid; `fbm2(s, x, y, 1) === valueNoise2(s, x, y)`.
- [ ] **Step 2:** Run `npm test`; expected: fails, modules not found.
- [ ] **Step 3: Implement `rng.ts`.** `mulberry32` is the standard algorithm (32-bit state, `Math.imul`, `>>> 0`, divide by `4294967296`). `hash2` mixes `seed`, `x`, `y` with `Math.imul` and xor-shifts and returns `(h >>> 0) / 4294967296`.
- [ ] **Step 4: Implement `noise.ts`.** `valueNoise2`: bilinear interpolation of `hash2` at the four surrounding lattice points, using `Math.floor` for the cell and the smoothstep weight `t*t*(3-2*t)`. `fbm2`: sum `octaves` layers, each with double the frequency and half the amplitude of the previous, each layer using `seed + octaveIndex`; divide by the amplitude sum.
- [ ] **Step 5:** Run `npm test`; expected: all pass.
- [ ] **Step 6:** Commit: `feat: seeded PRNG and value noise`.

### Task 4: Map generation

**Files:**
- Create: `src/sim/mapgen.ts`
- Test: `tests/mapgen.test.ts`, `tests/simPurity.test.ts`

**Interfaces:**
- Consumes: `fbm2` (Task 2), `GameMap`, `TileType` (Task 3).
- Produces:
  - `MAPGEN_CONFIG = { seaLevel: 0, maxHeight: 8, noiseScale: 1 / 32, octaves: 4, shoreDrop: 1, sandBand: 0.3, rockSlope: 0.9, rockAltitude: 4.5 }` (exported, mutable object; values may be tuned in Step 5).
  - `interface MapParams { seed: number; width: number; height: number }`
  - `generateMap(params: MapParams): GameMap` — `seed` is normalised with `>>> 0`.
  - `mapChecksum(map: GameMap): number` — 32-bit FNV-1a over the bytes of `heights` then `tiles`.

- [ ] **Step 1: Write failing tests in `tests/mapgen.test.ts`.**
  - Same params twice → `heights` and `tiles` arrays deep-equal and `mapChecksum` equal.
  - Seeds `1` and `2` at 128×128 → different checksums.
  - For seeds `1..5` at 128×128: every tile with `tx` or `ty` on the border is `Water`; the map contains at least 500 `Grass` tiles and at least 500 `Water` tiles; every tile value is `0..3`.
  - Non-square 64×32 map generates with correct array lengths.
  - `generateMap({ seed: -1, ... })` has `seed === 4294967295`.
- [ ] **Step 2: Write `tests/simPurity.test.ts`.** Read every `.ts` file in `src/sim` with `node:fs` and assert none matches `/from\s+['"]three/`, `/Math\.(random|sin|cos|tan|pow|exp|log|atan2)\b/`, `/\b(document|window)\./`.
- [ ] **Step 3:** Run `npm test`; expected: mapgen tests fail (module not found), purity test passes.
- [ ] **Step 4: Implement `mapgen.ts`.** Corner height:

```
dx = |cx / width  * 2 - 1|
dy = |cy / height * 2 - 1|
d  = max(dx, dy)                       // 0 at centre, 1 on the border
n  = fbm2(seed, cx * noiseScale, cy * noiseScale, octaves)
h  = maxHeight * n * (1 - d * d) - shoreDrop
```

  Tile type, from `avg` = mean of the four corners and `slope` = max corner − min corner, first match wins: `avg < seaLevel` → `Water`; `avg < seaLevel + sandBand` → `Sand`; `slope > rockSlope` or `avg > rockAltitude` → `Rock`; else `Grass`.
- [ ] **Step 5:** Run `npm test`. If the Grass/Water count tests fail for any seed, tune only the values in `MAPGEN_CONFIG` until they pass and record the final values in the task report. Expected: all pass.
- [ ] **Step 6:** Commit: `feat: deterministic island map generation`.
